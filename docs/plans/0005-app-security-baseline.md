# 方案 0005：authentik 应用层安全基线

- 状态：APPROVED（2026-09-28，操作者批准）
- 日期：2026-09-28
- 依据：[评审 0011](../reviews/0011-rebuild-direction-decisions.md)
- 关联：依赖[方案 0004](0004-deployment-foundation.md)的实例入口、`apply` 框架、备份恢复和 `breakglass` 应急入口

## 目标

接入真实用户和应用之前，建立一套认证与管理的安全基线。这套基线要能配置、能复现、能验证。上线门槛全部通过之前，服务保持在方案 0004 定义的“仅操作者”状态。

## 现状

`main` 41a6635 使用 authentik 2026.8.2 的默认配置：

- 没有自定义的蓝图、策略或角色；
- Caddy 只设置了 HSTS；
- akadmin 由 bootstrap 密码哈希创建。

main 上还没有任何应用层安全基线。

## 原则

1. **抗钓鱼 MFA 是核心控制。** 地理位置和网络信号是补充的防线。
2. **优先用 authentik 原生能力：** 蓝图、流程与阶段、策略、RBAC、通知。自研代码只负责校验、渲染、触发和核验。
3. **可调整的内容都作为设置数据**，包括是否要求 MFA；代码只负责逻辑和校验。
   - 弱于推荐值的设置，必须写进偏离清单并确认，每次检查都会报告。
   - 有偏离过期时，新的设置版本不能生效。当前已生效的版本不受影响，每天照常重新执行。
4. **必需设置缺失时，关闭依赖它的功能，而不是去掉控制本身。** 例如缺少 Turnstile 密钥时，登录失败，也不能对外开放。
5. **超级管理员是可信的最高权限。** 技术上无法阻止超级管理员削弱策略，只能靠通知和复核发现。

## 设置与 apply

**设置与渲染**

- 设置文件：`instance/settings/security.yaml`。仓库提供 JSON Schema 和推荐值模板，文件名在实现时确定。
- 渲染结果：一个认证链蓝图（包含流程、阶段、绑定、策略）和一份 Caddy 安全片段。
- 渲染用 YAML 序列化生成，不拼接字符串，也不执行设置中的任何代码。
- 渲染器为每个受管对象记录标识，即蓝图条目的 identifiers。与上一个生效版本相比，新版本不再包含的受管对象，会生成 `state: absent` 条目，确保它被删除。

**`apply` 步骤**

1. 校验设置和偏离清单。
2. 渲染到暂存目录，与上一个生效版本比较，输出脱敏后的差异。
3. 有差异时，先做一次数据库备份：用方案 0004 的 `backup`；异地仓库还没就绪时，至少用 `backup --local` 在本机保存一份。
4. 原子替换蓝图文件和 Caddy 片段，执行 `ak apply_blueprint`，然后平滑重载 Caddy。
5. 自动核验：经管理 API 回读受管对象和绑定，逐项与设置比对；对关键策略调用 authentik 的策略测试接口。
6. 如果核验失败：用上一个版本的渲染结果重新执行，其中包括删除新增对象的 `absent` 条目，然后再次核验。仍然失败时，停止并告警，给出第 3 步的恢复点。
7. 如果认证链有变化，由操作者用硬件密钥完成一次登录验证，并写入操作记录。

**为什么这样设计**

- authentik 在一个数据库事务里执行单个蓝图，失败时整体回滚；嵌套蓝图失败时只记日志。因此整条认证链放在同一个蓝图里，`apply` 期间不需要关闭入口。
- 蓝图执行成功之后，再执行旧文件并不会删除新版本新增的对象，只有 `state: absent` 才会删除。所以渲染器必须生成删除条目，回退才完整。
- 登录要经过 Turnstile，还要经过开启了用户验证的 WebAuthn。要自动完成登录，只能绕过验证码，或者在主机上保存软件密钥，两者都会削弱基线。所以自动核验只做回读和策略测试，登录验证由操作者手动完成。任何自动探测账号都需要单独设计并批准。

**漂移**

- 按 2026.8.2 源码，蓝图文件没有改动时不会被重新执行。
- 因此每日定时执行一次 `apply`：即使设置没有变化，也重新执行当前生效版本的蓝图，并报告被纠正的受管字段。
- 这项每日任务不受检查失败阻挡，见方案 0004「检查失败时各自阻止什么」。
- `check` 只读：回读并比对，报告漂移，不修改任何东西。
- 受管字段以设置文件为准；网页只管理明确开放的业务数据，例如用户和应用接入。

## 上线门槛

以下各项全部通过之前，服务保持在“仅操作者”状态。

### 认证

**身份识别阶段**

- 开启 “Pretend user exists”，关闭 “Show matched user”：不透露账号是否存在。
- 只接受用户名或邮箱。
- 加入 Turnstile 验证码阶段。

**密码**

- 至少 15 位，并开启 HIBP 泄露检查。
- 所有设置密码的路径都执行这条规则。

**MFA**

- 所有用户必须使用 WebAuthn。
- 用户验证设为 Required，最近验证阈值为 0。

**新用户**

- 由管理员创建。
- 新用户通过一个限时、只对该用户有效的链接设置密码并登记 WebAuthn。
- 登记完成之前，没有任何业务或管理访问权限。

**需要关闭的流程**

- 关闭注册、自助找回和无密码流程。做法是删除这些流程，或给它们绑定拒绝策略；只隐藏入口链接不够。
- 暂不启用 Passkey 自动填充。它会跳过验证码和后续的 MFA 阶段，是一条需要单独加固的路径。

**Turnstile 密钥缺失**

- 验证码阶段无法通过，登录失败。
- `check` 报告缺少密钥，并阻止对外开放。

**不可能旅行检测（所有用户）**

- 登录时，用 GeoIP 策略把本次位置与最近几次登录比较；换算出的移动速度超过阈值时，拒绝登录。
- 阈值是设置项。2026.8.2 中专门的“不可能旅行容差”字段不起作用，实际使用通用的距离容差，这一点在实测中确认。
- 这项检测来自操作者在草稿评审 0008 的决定（见评审 0011 摘录 Q12）。

### 管理员

**账号**

- 管理权限只授予专用管理员账号。个人日常账号不持有任何管理角色。
- `check` 核对：持有管理角色或超级用户权限的账号都属于管理员账号组，应急账号除外。

**硬件密钥的登记与验证**

- 管理员账号只能通过专用的登记阶段登记 WebAuthn。这个阶段的型号限制只列出认可的硬件密钥，不包括“未知设备”。
- 普通登记流程通过策略拒绝管理员组成员使用。
- 管理员的验证阶段使用同一份型号列表。列表不能为空，因为 authentik 把空列表当作“全部允许”。
- 每位管理员两把硬件密钥，当面登记，其中一把作为备用离线保管。

**型号限制的局限**

- authentik 不校验认证器的证明链，型号由认证器自己上报。
- 验证阶段会放过没有记录型号的凭据：未知 AAGUID 登记后不带型号；FIDO 元数据撤销某个型号后，已登记的设备也会失去型号。
- 因此另外依靠：
  - 新设备登记时发出通知；
  - 每月复核管理员设备清单；
  - `check` 发现管理员名下有未记录型号的设备时，报错并告警，阻止切换到“公开”。

**会话**

- 会话时长 8 小时。
- 不提供“保持登录”，登录时结束其他会话，关闭设备记忆。
- 会话按 ASN 与网络绑定。这是操作者在草稿评审 0008 的选择：客户端的网络变化后需要重新登录；GeoIP 数据缺失时会话直接结束。

**登录地区**

- GeoIP 策略只允许 JP 和 US，这是一个设置项。
- GeoIP 数据的来源见方案 0004：MaxMind 配置留空时用镜像自带库，填写后由 geoipupdate 自动更新。
- 查不到位置时策略出错，绑定的失败结果设为拒绝。

### 普通用户会话

**规则**

- 使用浏览器会话，可选“保持登录” 7 天。
- 不按 ASN 或网络绑定：操作者此前决定不做这种绑定，因为切换 Wi-Fi 和移动网络会被登出。
- 另加一层国家级会话绑定，即 User Login 阶段的 GeoIP 绑定：
  - 客户端 IP 变化时才核对；
  - 在同一国家内切换网络，不受影响；
  - 从其他国家重放会话 cookie，会被拒绝；
  - GeoIP 数据缺失时，会话直接结束。

**与不可能旅行检测的分工**

- 不可能旅行检测只在登录时起作用，挡不住已登录会话的重放。
- 国家级会话绑定补上跨国重放这一块。
- 两者都挡不住同一国家内的重放，例如经本国住宅代理发起，见风险。

### 权限

**角色与授权**

- 日常管理使用角色和对象权限。超级用户只给应急账号，以及少数必须由超级用户执行的操作。
- 权限矩阵单独列出以下写入权限：角色定义、授权变更、认证流程与阶段及其绑定、品牌、恢复、通知规则等。
- 敏感授权不分配给日常角色。

**给管理员账号授予敏感角色的顺序**

1. 核验身份和合规设备；
2. 暂停该账号；
3. 撤销旧会话；
4. 授予权限；
5. 经管理员登录流程重新登录。

**需要关闭的功能**

- 关闭 impersonation，但保留“需要理由”的设置。
- 关闭内嵌 outpost（`AUTHENTIK_OUTPOSTS__DISABLE_EMBEDDED_OUTPOST=true`）。按源码推断，它存在时，`AUTHENTIK_SECRET_KEY` 可以当作它的 API 令牌使用。

**令牌**

- 自动化只使用受限服务账号的令牌。
- 个人高权限账号不持有长期令牌，由 `check` 报告。
- 每月复核令牌和 Tunnel 连接器。

**akadmin**

- 个人管理员账号和应急账号都就绪后，停用 akadmin，并从 `.env` 删除所有 BOOTSTRAP 值。
- 不要删除或改名 akadmin。按源码推断，`system/bootstrap.yaml` 重新执行时，会用 `.env` 中的哈希把缺失或改了名的 akadmin 重建为超级用户。
- akadmin 停用后，`check` 按键名核对 `.env` 中不再有 BOOTSTRAP 项，不读取任何值。

### 防滥用

**Turnstile**

- 使用托管模式。
- 在 Cloudflare 侧把小组件的主机名列表限定为认证域名，因为 authentik 不校验返回的 hostname。
- 验证服务故障时，拒绝新的浏览器登录，但不影响 token、userinfo 等后端接口。

**信誉策略**

- 按 IP 计分，分数不高于阈值（默认 −5）时拒绝。
- 这个策略在分数不高于阈值时判定为“通过”，所以绑定为拒绝时需要取反。
- 不按用户名拒绝，否则任何人都能把已知账号锁住 24 小时。
- 按用户名统计的失败只用于告警。

### 入口与响应头（Caddy）

**路径限制**

- 公网对以下路径的所有方法一律拒绝。这与官方加固指南一致，也是操作者在草稿评审 0008 的决定（评审 0011 摘录 Q15、Q16）：
  - `/api/v3/policies/expression*`
  - `/api/v3/propertymappings*`
  - `/api/v3/stages/prompt/prompts*`
  - `/api/v3/managed/blueprints*`
  - `/api/v3/stages/captcha*`
- 清单本身是设置项。
- 测试大小写、重复斜杠和编码变形能否绕过这些限制。

**对管理界面的影响**

- 整条路径屏蔽后，管理界面中接入应用的表单可能读不到属性映射。这一点在清单 C0 中实测。
- 草稿当时的设想是：管理员查看这些对象时改走本机回环端口。但在 Tunnel 架构下，经回环地址无法用硬件密钥登录，因为 WebAuthn 与域名绑定，所以这个办法不再可行。
- 如果实测确认受影响，由操作者二选一：
  1. 对这些路径放行只读（GET），作为偏离写入偏离清单；
  2. 应用接入改为在主机上用蓝图或 API 完成。

**响应头**

- CSP：
  - 以官方推荐的基础策略为起点；
  - 加上 `frame-ancestors 'self'` 和 Turnstile 需要的来源；
  - 不覆盖 authentik 自己设置的 CSP。
- HSTS：初始值为 `max-age=86400`，不包含子域，确认没有问题后再提高。
- `Referrer-Policy: strict-origin-when-cross-origin`。
- `X-Content-Type-Options: nosniff`。

### 事件与通知

**通知规则覆盖的事件**

- 管理员登录；
- 登录失败（聚合后通知）；
- 可疑请求；
- 权限、组、角色变化；
- 设备登记与删除；
- 恢复链接使用；
- impersonation；
- `model_*`、`secret_view`；
- 策略异常。

**发送渠道与保留**

- 同时发送邮件（经 mailcow SMTP）和本机以外的 webhook。主机或邮件出故障时，webhook 那边仍有副本。
- 事件保留 365 天，这是设置项。
- 审计差异和导出属于企业版功能，方案不依赖它们。

### 应急与恢复

**应急账号**

- 设两个应急账号，都是本地超级用户，不对应具体个人。
- 每个账号配一把 FIDO2 硬件密钥，两把分开存放。
- 每次登录都发通知，每 90 天演练一次。

**管理员丢失一把密钥**

- 用备用密钥登录，撤销丢失的设备，再登记新设备。

**全部丢失或无法登录**

1. 操作者核验身份后，在主机上执行 `ak create_recovery_key <分钟> <用户>`，得到一个一次性、限时的直接登录链接。这个链接不经过登录流程和 MFA。
2. 平时经公网主机名打开这个链接。
3. Cloudflare 不可用时，改经 `breakglass` 回环入口打开。这时只能在管理界面修复配置、撤销设备，不能登记新设备，因为 WebAuthn 需要生产域名；登记新设备要等公网恢复后再做。
4. 登记新设备后，撤销临时会话。恢复事件会发送通知。

**不设应急模式**

- 不设任何能从网络访问的“应急模式”。
- 不信任任何“应急来源”地址。

## 不在本期

- LDAP、RADIUS 和 Proxy outpost；
- 具体业务应用的接入；
- 企业版功能；
- 自建审批平台。

以下候选工作各自需要单独规划，不属于本方案：

- 防账号枚举的时序分析；
- 数据库 TLS；
- 设备与令牌的自动复核报告。

## 验收

| 条件与操作 | 应看到的结果 | 证明方式 |
|---|---|---|
| 修改国家、时长、型号、路径清单 | 不改代码即可生效 | `apply` 输出与回读 |
| 提交非法设置，或存在已过期的偏离 | 新的设置版本不能生效，当前状态不变，每日重新执行照常进行 | 测试 |
| 蓝图执行失败 | 整体回滚，旧配置继续生效 | 测试 |
| 蓝图执行成功，但核验失败 | 回退后受管对象与上一版本一致，新增的对象已删除 | 回读比对 |
| 重复执行 `apply` | 没有变化 | 回读比对 |
| 在网页上修改受管字段 | `check` 报告漂移，每日 `apply` 将其纠正 | `check` 输出 |
| 用存在和不存在的用户名分别登录 | 身份识别阶段的响应内容和状态一致，不透露账号是否存在 | 测试 |
| 用密码登录；直接访问流程地址 | 都要求 Turnstile 和 WebAuthn，没有绕过的路径 | 操作者手动测试记录 |
| 在任一设置密码的路径上使用短密码或已泄露的密码 | 被拒绝 | 测试 |
| Turnstile 密钥缺失 | 登录被拒绝；`check` 报告并阻止对外开放 | 测试 |

## 风险

- **管理员被锁在外面：** 可能源于错误的 `apply`、GeoIP 数据问题或不可能旅行误判。
  - 应对：应急账号和主机上的恢复链接；`apply` 前的备份；认证链每次变化后的手动登录验证；阈值可调。
- **Cloudflare 或 Turnstile 故障：** 新登录会失败，已经登录的会话不受影响。
  - 应对：经 `breakglass` 修复配置，但这时不能登记新设备。
- **同一国家内的会话重放：** 会话 cookie 被盗后，如果从同一国家发起重放，例如经本国住宅代理，普通用户的国家级绑定挡不住。
  - 应对：缩短会话时长，并靠告警与复核发现。管理员的 ASN 与网络绑定能挡住大部分这类重放。
- **不可能旅行误判、出境后被登出：**
  - VPN 或 IP 定位误差可能导致正常登录被拒绝；
  - 普通用户出境后 IP 换到另一个国家，会话会被结束，需要重新登录。
  - 应对：阈值可调；拒绝会记录并告警。
- **共享 IP 被信誉策略拒绝：** 在运营商 NAT 或公司网络等共享 IP 后面的正常用户，可能被拒绝长达 24 小时。
  - 应对：阈值可以调整；拒绝事件会告警，必要时临时放宽，并记入偏离清单。
- **超级管理员削弱策略：** 技术上无法阻止。
  - 应对：依靠通知和复核发现。
- **GeoIP 库过旧导致误判：**
  - 应对：填写 MaxMind 配置后自动更新；未填写时随补丁节奏更新镜像。`check` 报告库的构建时间。
